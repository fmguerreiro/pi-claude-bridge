# Changelog

## Fork (fmguerreiro) — OMP support + open-issue sweep

- **New: runs on Oh My Pi (OMP)** — adds an `omp.extensions` manifest entry and adapts the host API surface: helpers OMP does not export (`compact`, `generateBranchSummary`, `buildSessionContext`, `keyHint`, `formatSkillsForPrompt`) are probed dynamically or supplied locally, system prompts arriving as `string[]` are normalized, and lifecycle takeovers install only where the host supports them. Under an OMP agent dir, Claude setting sources default to `[]` and project config is ignored, so an untrusted repo cannot swap the Claude executable. Based on PR #63 by @dpaluy.
- **Fix: tool calls were denied outright under OMP** — the bridge relied solely on `permissionMode: "bypassPermissions"`, which silently degrades to `"default"` when managed/remote Claude settings set `disableBypassPermissionsMode`. Claude Code then refused to dispatch its own `mcp__custom-tools__*` calls, so the host executed the tool but no MCP handler was waiting (`0 waiting handlers`) and the model reported a permission error. The served tools are now declared as `allowedTools`, which lands in Claude Code's `cliArg` rule destination and so survives settings reloads and needs no setting sources. Pi only ever worked here by accident of a user-level auto-approve hook.
- **Fix: OMP `developer`-role messages were dropped, and a trailing one produced a bogus `[continue]` turn** — `turnStart` only walked back over `user` messages and `convertPiMessages` dispatched only `user`/`assistant`/`toolResult`, so OMP's developer messages never reached Claude and a trailing one left the turn with no prompt, sending the literal recovery prompt `[continue]`; that reply then overwrote the real answer. Developer content is now folded onto a user-role message, framed by attribution: user-attributed content (an `@file` mention's text) keeps its shaping, while agent-attributed host steering (prewalk, plan-mode, rewind, auto-continue) is marked as mid-task guidance so the model continues the user's original request instead of answering the nudge.
- **Fix: debug and CLI logs wrote into `~/.pi/agent` under OMP** — they now follow the active agent dir, honoring profiles, `PI_CODING_AGENT_DIR`, and the `CLAUDE_BRIDGE_DEBUG_PATH` override.
- **Fix: every `isolated: true` subagent failed (issue #64)** — `promptCaptures` was module-instance state while the active stream is pinned process-wide, so an isolated child recorded its prompt into one registry and the parent stream looked it up in another. The registry is now shared through `Symbol.for`, matching the existing pinned-stream idiom, and stays bounded at 256 entries.
- **Fix: spawning any subagent under OMP failed with `No API key for provider: claude-bridge`** — a later module instance skipped `registerProvider()` entirely, on the assumption that the parent's entry in a shared registry would still be there. OMP clears every provider entry owned by an active extension source at each session init and then re-applies only that session's queued registrations, so the skip dropped the `claude-bridge` api and its apiKey out from under both the child session and the parent that shares the registry; the parent's next stream — the one that delivers the pending `task`/`hub` tool result — then died at credential resolution, stranding the turn (`session_shutdown left state behind — pendingToolCalls=1`). Every instance now registers, always passing the *pinned* first instance's `streamSimple`, so a child can never displace the parent's stream reference, which is what skipping was protecting under Pi.
- **Fix: compaction was silently undone (issue #62)** — the completion handler rebuilt the shared session as a fresh object, discarding a `needsRebuild` set by a compaction still generating its summary; the cursor also stayed pinned at its pre-compaction high-water mark, arming the shorter-context branch on every later turn. Flags now survive the completion write and the cursor tracks current history.
- **Fix: a shrunken history no longer clean-starts (issues #30, #55)** — when pi's history shrinks (`pi-context-prune`, compaction, a replayed deferred message), the bridge ran the turn with no `--resume` and no imported messages, so the model answered with zero context, silently. It now rebuilds from pi's current compressed history, and the clean-start branch is reachable only for the reentrant subagent case it was actually written for.
- **Fix: rebuilt sessions could use the wrong model (issue #42)** — rebuilds passed the bare `model.id` instead of the resolved long-context id, and a mid-session `model_select` did not invalidate, so the next turn could resume a session created for the previous model and fail with `Prompt is too long`.
- **Fix: subscription limits never triggered pi's fallback (issue #58)** — an exhausted quota surfaced as a plain result string, so `fallbackModels` never engaged. Limits are now classified as rate-limit-class errors that pi's `isRetryableAssistantError` recognizes; genuine billing/auth walls stay non-retryable and are reported verbatim.
- **Fix: transient overloads failed the turn (issue #43)** — a 529 before anything streamed now retries once after 800ms, regenerating the single-use prompt iterable; usage-limit, quota, auth, payment and permission errors are never retried, and an error after output has started is returned unchanged so nothing is duplicated.
- **Fix: half-open streams hung forever (issue #35)** — a tool-aware idle watchdog aborts a stream that stops producing events without throwing, surfacing a retryable error; it never fires while a tool call is in flight.
- **Fix: tool calls leaking as literal `<invoke>` text stalled the agent (issue #36)** — a turn ending on literal invoke text with no structured call now synthesizes a real tool call, and a stale literal draft alongside a genuine call is suppressed from the visible text. Argument types come from the tool's declared schema, so a file body of `42` or a commit message of `true` stays a string.
- **Fix: AskClaude's schema misreported its configured defaults (issue #65)** — the model-facing text hard-coded `mode: "read"` and `isolated: false`, so under `defaultMode: "full"` a model that omitted `mode` got write and bash access while the schema promised read-only. Schema, description and TUI now derive from the effective config, `allowFullMode: false` removes `"full"` from the enum, and an inherited `isolated` is shown rather than hidden.

## UNRELEASED

- **Fix: compaction freed nothing on the wire, driving the host into a compaction loop** — `needsRebuild` and `cursor` both live on `sharedSession`, which only the pinned module instance holds, but `session_compact` fires on the instance owning the *compacting* session. `markRebuild` running anywhere else returned at its own null check, leaving no trace, and the cursor kept whatever a short-context query last wrote — so both REUSE guards passed on a conversation the host had just rewritten and the pre-compaction Claude Code session was resumed unchanged. Observed on OMP as five consecutive compactions inside four minutes with no cache break at any of them (`cache_creation` never above the per-turn delta while `cache_read` climbed 306k → 319k), each freeing ~200k tokens on the host's side and none on the wire, until the host's own loop guard paused automatic maintenance. Invalidation now also bumps a history epoch held in a `Symbol.for` global, keyed by host session id, that REUSE must still match; keyed per session rather than process-wide because with every role routed through this provider a subagent compacts constantly, and one global counter would charge the parent a full rebuild each time. A failing query that never owned `sharedSession` also no longer discards it, which silently disarmed `markRebuild` the same way.
- **Fix: a subagent could take over — and answer out of — the parent's Claude Code session** — `foreignConversation` came only from `sharesSubstantialPrefix`, which prompt-capture sets only on a pass-through prompt. That covers OMP's side agents but not a subagent: under OMP a child's prompt is recorded exactly like its parent's, so no field on either capture separates them. A child dispatched inside its parent's turn is no longer reentrant by the time its own call lands, so it took REUSE/REBUILD against the parent's session and published its own id on completion; the parent's next turn then resumed the child's transcript. Verified live on OMP: asked for a codeword from its own first message, the parent replied with the subagent's output. The host's session id now classifies those queries, claimed by the first non-reentrant query so start order decides and never completion order — a fast child can finish before its parent's opening turn, and letting a completion claim ownership would hand it the session and then refuse the parent's own write. Inheritance is deliberately not used for this: an extension that wraps a recorded prompt produces the same non-empty `inherited` as a subagent does, so keying on it isolates a real turn from its own session. Covered by `tests/int-subagent-delayed-dispatch.mjs`, which fails on the unfixed bridge.
- **Fix: `/compact` and rewind-with-summarize were broken on whichever host was not the one the call was written for** — Pi's `compact` takes 11 positional arguments with `streamFn` 8th; OMP's takes 6 and carries the override in an options object. Only one shape was ever sent, and getting it wrong is silent rather than a type error: the wrong slots take the wrong values, the summarization override is dropped, and the host falls back to resolving the bridge model through its own provider — `No API key for provider: claude-bridge` on OMP, `No API provider registered for api: claude-bridge` on Pi, each surfacing as a cancelled compaction. Both shapes are now declared separately and selected by `compact`'s arity, so each call is type-checked against the host it is going to, and the message-shaped summary is replayed as a stream for Pi's `streamFn`. Arity rather than the agent dir, so the temporary `PI_CODING_AGENT_DIR` every integration test sets cannot fool it. `tests/unit-host-compact-shape.mjs` pins it from both ends: every installed host really has the arity the dispatcher keys on and really calls the override it is handed, and the dispatcher maps that arity to the shape written for it. Hosts that are not installed are skipped.
- **Fix: better isolate AskClaude tool (issue #59)** — AskClaude children no longer inherit the user's `~/.claude` `CLAUDE.md` files or skill listing, and now always get Claude Code's system prompt preset instead of only when pi-side skills exist. Thanks @JAtkinsonKO.
- **Fix: Bogus debug message about "record count mismatch" after switching providers** — the post-rebuild integrity check did not take `@file` expansion into account when switching providers.
- **Fix: OMP's advisor, title generator and idle recap never worked on this provider** — those agents assemble their own system prompt without routing it through `before_agent_start`, so `PromptCaptures.resolveOrDerive` matched neither an exact key nor an embedded one and threw, failing every turn they ran (the advisor halts itself after three). An unaccountable prompt now passes through losslessly instead, projected back out byte-for-byte, since whatever assembled it already rendered its own context files and skills into the text. A prompt that shares a substantial prefix with a capture this bridge did record only means something rewrote it if that capture also carried portable structure — context files, skills, an append, or a `custom` narrower than its assembled prompt — since a capture with none of that already projects to its own bytes. OMP's own captures never carry that structure, so the prompts OMP legitimately rebuilds mid-session (memory promotion, compaction, tool-registry changes) stay quiet instead of falsely flagging every one of them; only a genuine rewrite of a capture that would have projected to something else is reported through `piUI.notify`. Fixing the throw surfaced a second bug: once these side-agent queries actually reached the provider, `syncSharedSession` mistook each one for the main conversation — it fired the "this turn is running without conversation history" notify on every side-agent turn, and worse, overwrote the module-level shared session with the side agent's own session id and cursor, so the two conversations then fought over one session slot on every later turn. `PromptCapture` now separately records whether a pass-through shares a substantial leading prefix with a recorded capture (`sharesSubstantialPrefix`, independent of `passthroughRisk`'s portable-structure check): no shared prefix means a different conversation this bridge never recorded, not a rewrite of this one. `syncSharedSession` takes a `foreignConversation` flag derived from that field and, for a foreign conversation, imports the side agent's own priors into a session of its own without ever reading, writing, reusing or deleting the main conversation's `sharedSession`, and without the notify.

## 0.7.0 — 2026-08-08

- **BREAKING: AskClaude tool now off by default** — If you want to continue using the AskClaude tool, set `askClaude.enabled` to `true` in your config (see README.md).
- **New: mid-turn steering actually works (issue #39)** — a steer sent while a tool was running used to be stashed and replayed as a follow-up after Claude's whole turn finished. The prompt is now a long-lived streaming generator and the steer is written to CC's stdin (`priority: "next"`) before the tool result is released, so CC drains it at that tool boundary and acts on it in the same turn.
- **Fix: system prompt loading** — Claude Code now receives the same global and hierarchical `AGENTS.md` / `CLAUDE.md` files that Pi loads. Config settings`provider.appendSystemPrompt` / `provider.settingSources` are no longer needed and have been removed gone). Improved compatibility with for children agent (i.e. subagents) and for other extensions that modify the system prompt. Unhandled system prompt configurations should fail loudly rather than silently discarding instructions.
- **Fix: branch summarization ran through the live provider** — rewinding or forking with "summarize" runs through the *agent's* stream function, so unlike `/compact` the request reached this provider and the live Claude Code session rather than an isolated subprocess. The bridge now takes over `session_before_tree` the way it already took over `session_before_compact`.
- **Fix: `@file` mentions were lost when a session was rebuilt** — Claude Code expands an at-mention itself (unlike pi) and stores the file's contents as an `attachment` record in its own session file; pi never sees it, so a rebuild kept the prompt text and silently dropped the file the model was reasoning about. Expansions are now carried across. Requires cc-session-io `^0.4.0`.
- **Fix: images dropped from prompts and rebuilt sessions (issue #34)** — an image followed by a trailing text preview lost the image, and tool results carrying images were flattened to text whenever the bridge rewrote pi's history into a Claude Code session. Images survive both paths now.
- **Fix: session rebuilds could corrupt turn structure** — pi records one message per tool result, and `repairToolPairing` (applied inside `Session.importMessages`, so unavoidable) only pairs results sharing the user message right after their assistant message, so tool results past the first can become `[no tool result recorded]`; a turn's results are now collected into one message placed directly after its assistant message. Minor: a turn aborted before anything streamed was rebuilt as `[incompatible content omitted]` potentially misleading the agent into thinking it is missing something. Empty turns are dropped now, while genuinely filtered content keeps its slot and label. Rebuilds also incorrectly wrote pi's bare model id instead of the resolved CLI id, dropping the `[1m]` suffix (issue #42; minor metadata fix only, since `--model` was already correct).
- **Fix: errored turns could report as a successful stop** — CC flags failures with `is_error` on a result whose subtype is still `"success"`, so the bridge duplicated the error text and finalized normally (issue #43); failed results now end the turn with `stopReason: "error"`, and the compact-summary path no longer accepts an errored result. Separately, a turn that ended on a tool call has its pi stream closed, and the guard suppressing content events for a closed stream also swallowed the `result` message, so a 429 or overload mid-tool set no `stopReason` and logged nothing (part of issue #35). The no-event stream watchdog idea in #35 has not been addressed.
- **Fix: a reentrant subagent could disturb the parent's session** — the shared session cursor was written from whichever context delivered tool results, so a background subagent dragged the parent's cursor backwards and cost its next turn a full rebuild and a flushed prompt cache. Removal from the active-context set is now guarded like the cleanups beside it, and an orphaned tool result no longer resets the live top-level context's turn state.
- **Fix: bridge could deadlock on a tool name Claude can't call** — Claude sometimes called `bash` instead of `mcp__custom-tools__bash`; CC rejected it with "No such tool available" and retried under a fresh tool_use id, but the bridge had already run the rejected call, so the retry's MCP handler waited on a result that never came. Calls for anything the bridge does not serve over MCP are now ignored. Rebuilt transcripts contributed to this by sometimes naming tools as `Bash`/`Read`/`Edit`/`Write` in past calls; those names now stay in the `mcp__custom-tools__` namespace.
- **Fix: nested tool schemas flattened (issue #44)** — converting pi schemas to Zod collapsed nested objects and dropped `anyOf`/`const`, so Claude saw only the top level of tools like `edit` and `subagent`. The MCP server now serves pi's JSON Schema verbatim.
- **Fix: tool results paired by call order** — MCP handlers took their `toolCallId` from a positional cursor, so a call arriving out of order silently paired its result with the wrong tool call. Now pairs by Claude's `_meta["claudecode/toolUseId"]` and fails loudly if it is absent.
- **Fix: Claude Code could write memory from bridge turns** — provider and AskClaude queries now disable auto-memory through the SDK; set `provider.autoMemoryEnabled` to `true` to opt in if you actually want it. Isolated compaction queries always disable it.
- **Tests: suites now drive the real code** — `tests/lib/record-sdk-streams.mjs` captures verbatim SDK streams (scrubbed, and refusing any fixture the username survived) for `tests/unit-stream-replay.mjs`, replacing hand-written messages that missed the `system/status` and `rate_limit_event` frames a real stream carries. `tests/int-shutdown-kills-cc.mjs` pins that a pi shutdown and a user abort each reap the Claude Code subprocess with a tool call in flight.
- **Tests: correctness audit tooling** — `diag/audit-{transcripts,cache,warnings}.mjs` scan session transcripts and the bridge log for silent data loss, prefix-cache breaks and stranded tool handlers, gated on `--since`; `diag/replay-write-path.mjs` replays any pi session through the rebuild. `tests/int-cc-contracts.mjs` pins the undocumented Claude Code behavior the bridge depends on against the installed SDK, and `tests/unit-convert-determinism.mjs` pins that a rebuild is deterministic and extends the previous transcript rather than rewriting it.
- **Internal: trim redundant dependencies** — pi bundles typebox and its extension loader always aliases the import to that copy, so shipping our own only made consumers install a redundant one that pi ignores. Now `peerDependencies: "*"` plus a devDependency for typechecking, as pi's packaging docs require; dev peers track pi 0.83.0. `@anthropic-ai/sdk` moves to devDependencies for the same reason — it is only ever imported for types.

## 0.4.0 — 2026-05-04

- **Fix: Opus 4.7 + xhigh sent wrong effort to SDK** — pi-ai 0.72 ships per-model `thinkingLevelMap` overrides (e.g. `claude-opus-4-7` declares `xhigh→xhigh`, not `xhigh→max`), but our hardcoded `REASONING_TO_EFFORT` table ignored them. Effort lookup now consults `model.thinkingLevelMap` first, falls back to the table for older pi-ai or unmapped levels. Forwarded `thinkingLevelMap` through `buildModels` projection.
- **Fix: zero out model cost in `buildModels`** — per-token pricing in the footer was wrong because models inherited pi-ai's non-zero cost fields, which pi then multiplied by the huge token counts from the SDK. Now explicitly zeroed so pi's footer shows no cost.
- **Use `tools: []` instead of `disallowedTools` blocklist** — switch from blocking specific tools to explicitly passing an empty tools list, preventing any new default tools from silently leaking into bridge sessions.
- **Disable CC-side autocompact (`DISABLE_AUTO_COMPACT=1`)** — pi already owns context management and propagates its own `/compact` to CC. Letting CC autocompact too double-flushed the prompt cache and raced pi's threshold; manual `/compact` in CC is unaffected.
- **Fix: pi `/compact` no longer triggers CC autocompact-thrashing (issue #8)** — pi's compaction shrinks its messages array, but `syncSharedSession`'s REUSE check (`slice(cursor)`) silently returned `[]`, so the bridge kept `--resume`ing the pre-compact CC session JSONL. Over long sessions CC's own autocompact then refilled within 3 turns and tripped its anti-thrashing guard. Now subscribes to pi's `session_compact` event and forces the next sync down the REBUILD path so CC sees the post-compact history. Also subscribes to `session_tree` (branch nav has the same shape).
- **Refactor: split `needsRebuild` into `needsRebuild` + `forceRotate`** — only the abort case needs UUID rotation (to dodge late writes from the dying CC subprocess). Compact/tree now rebuild in place, preserving the sessionId and not leaking orphan JSONL files into `~/.claude/projects/`.
- **Block user-installed MCP servers from leaking into bridge sessions** — pass `--strict-mcp-config` unconditionally and set `ENABLE_CLAUDEAI_MCP_SERVERS=0` in the spawned CC env, suppressing both filesystem (`~/.claude.json`, `.mcp.json`) and claude.ai cloud MCP servers. Override with `provider.strictMcpConfig: false`.
- **Consolidate config** — SDK plumbing (`appendSystemPrompt`, `settingSources`, `strictMcpConfig`) moved from `~/.pi/agent/settings.json` (`claudeAgentSdkProvider` block) to a `provider` block in `~/.pi/agent/claude-bridge.json`. Old location no longer read. Drop deprecated, unsafe `maxHistoryMessages`.
- **Bump deps** — `@anthropic-ai/claude-agent-sdk` → ^0.2.126; migrate to TypeBox 1.x (new import paths per pi-mono 0.69); pi devDeps → ^0.72.1. Extract `registerTool` schemas to const with explicit `<typeof params>` generic to avoid TS2589 deep-instantiation under TypeBox 1.x.
- **Internal: move sources into `src/`** — `index.ts` and the extracted modules now live under `src/`; screenshots under `assets/`. `pi.extensions` and published `files` updated accordingly.
